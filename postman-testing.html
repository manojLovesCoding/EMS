Postman Testing Guide

Complete testing documentation for the Leave Management module using Postman. This guide covers authentication, leave applications, approval workflows, leave balance calculations, and unpaid leave allocation.

2. Postman Testing Setup

First, create a new Postman environment to manage the API configuration and reusable variables.

Environment Variables

Variable Value
baseUrl http://localhost:5000
leaveId ID returned from POST request
employeeEmail Employee login email
adminEmail Admin login email
Note: Change port 5000 if your backend uses a different port.

Authentication Before Testing

Your controller uses req.session, so you must authenticate through your existing login API before testing.

  1. Login as an employee.
  2. Make sure Postman retains the session cookie.
  3. Run employee requests.
  4. Login as admin before approving or rejecting leave.
  5. Switch back to employee login when checking the employee balance.
Important: Postman normally manages cookies automatically. If necessary, open Cookies and verify that your session cookie is present for localhost.

01 Get Employee Leave Balance

Login as the employee who joined November 2, 2026. Retrieve the employee's current leave balance.

GET {{baseUrl}}/api/leave

Expected Balance — November 12, 2026

Assuming no approved regular leave:

{
  "balance": {
    "leaveYear": {
      "start": "2026-05-01",
      "end": "2027-04-30"
    },
    "regular": {
      "earned": 0.5,
      "used": 0,
      "available": 0.5
    },
    "sick": {
      "allowance": 4,
      "used": 0,
      "available": 4
    }
  }
}
The actual response also contains data and employee.
Expected Status: 200 OK

02 Apply for Half-Day Regular Leave

Login as employee and create a half-day regular leave application.

POST {{baseUrl}}/api/leave

Request Body → raw → JSON

{
  "type": "REGULAR",
  "startDate": "2026-11-16",
  "endDate": "2026-11-16",
  "startDayType": "HALF",
  "endDayType": "FULL",
  "reason": "Personal work"
}

Expected Response

{
  "success": true,
  "data": {
    "_id": "YOUR_LEAVE_ID",
    "type": "REGULAR",
    "totalDays": 0.5,
    "status": "PENDING"
  }
}
  • Status: 201 Created
  • totalDays: 0.5
  • status: PENDING
Save the returned _id in your Postman leaveId environment variable.

03 Approve Half-Day Leave

Login as ADMIN before approving the employee's application.

PATCH {{baseUrl}}/api/leave/{{leaveId}}

Request Body

{

}

    "paidDays": 0.5,
    "unpaidDays": 0,
    "paidRegularDays": 0.5,

  }

Expected Status: 200 OK

05 Test Unpaid Leave Allocation

The employee now has zero remaining regular leave. Apply for one full day to verify unpaid leave allocation.

POST {{baseUrl}}/api/leave

Request Body

{
  "type": "REGULAR",
  "startDate": "2026-11-17",
  "endDate": "2026-11-17",
  "startDayType": "FULL",
  "endDayType": "FULL",
  "reason": "Personal work"
}

Save the new ID and approve the application as ADMIN.

Expected Approval Response

{
  "status": "APPROVED",
  "totalDays": 1,
  "paidDays": 0,
  "unpaidDays": 1,
  "paidRegularDays": 0,
  "unpaidRegularDays": 1,
  "unpaidDateBreakdown": [
    {
      "date": "2026-11-17T00:00:00.000Z",
      "days": 1
    }
  ]
}
Expected Result: The employee can still apply for leave even when paid leave is exhausted. The remaining leave becomes unpaid.

06 Test No Advance Leave

Use a fresh employee who joined November 2, 2026, and has not used any regular leave.

On November 12, apply for one full day.

POST {{baseUrl}}/api/leave

Request Body

{
  "type": "REGULAR",
  "startDate": "2026-11-18",
  "endDate": "2026-11-18",
  "startDayType": "FULL",
  "endDayType": "FULL",
  "reason": "Personal work"
}

Approve it as ADMIN.

Expected Response

{
  "totalDays": 1,
  "paidDays": 0.5,
  "unpaidDays": 0.5,
  "paidRegularDays": 0.5,
  "unpaidRegularDays": 0.5
}

Why?

  • November credit = 0.5.
  • December credit = 0.5.
  • Current date = November 12.
  • December credit is not yet available.
Conclusion: Only 0.5 days can be paid. The remaining 0.5 days will be unpaid.

07 Test Monthly Carry-Forward

Use a fresh employee who joined November 2, 2026. Check the leave balance at different dates.

Check Date Earned Used Available
Nov 12, 2026 0.5 0 0.5
Dec 1, 2026 1.0 0 1.0
Jan 1, 2027 1.5 0 1.5
Feb 1, 2027 2.0 0 2.0

Example: December 1 Balance

{
  "regular": {
    "earned": 1,
    "used": 0,
    "available": 1
  }
}
Expected Result: November's unused 0.5 credit carries forward and combines with December's 0.5 credit.
Note: This test requires checking on the actual dates. Don't manually change your computer clock in production.

08 Test Rejected Leave

Create another leave application and reject it as ADMIN.

PATCH {{baseUrl}}/api/leave/{{leaveId}}

Request Body

{
  "status": "REJECTED"
}

Expected Response

{
  "success": true,
  "message": "Leave rejected successfully."
}

Verify Employee Balance

  • Rejected application does not consume paid leave.
  • Available regular leave remains unchanged.
Expected Result: Rejected leave does not affect the employee's paid leave balance.

09 Test Sick Leave

Login as employee and apply for two days of sick leave.

POST {{baseUrl}}/api/leave

Request Body

{
  "type": "SICK",
  "startDate": "2026-11-19",
  "endDate": "2026-11-20",
  "reason": "Not feeling well"
}

Approve the application as ADMIN.

Expected Approval Response

{
  "status": "APPROVED",
  "totalDays": 2,
  "paidDays": 2,
  "unpaidDays": 0,
  "paidSickDays": 2,
  "unpaidSickDays": 0
}

Expected Sick Leave Balance

{
  "sick": {
    "allowance": 4,
    "used": 2,
    "available": 2
  }
}
Expected Result: Two days are deducted from the four-day sick leave allowance.

10 Admin Gets All Pending Applications

Login as ADMIN and retrieve all pending leave applications.

GET {{baseUrl}}/api/leave?status=PENDING

Expected Response

{
  "data": [

      "status": "PENDING",
      "employee": {
        "firstName": "John",
        "lastName": "Doe"
      }
    }
  ]
}
Your actual response includes the populated employee document and other leave fields.
Expected Result: Admin can retrieve pending leave applications successfully.
